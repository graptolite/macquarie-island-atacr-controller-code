Most steps of this process are parallelised, with the number of cores controlled by `<ncores>`. [SeisMem](https://github.com/graptolite/seismem) must be present and its path correctly identified in `identify_seismem.py`.

`00_combine_days.py <channel> <ncores>` is to be run on each channel ("HZ","H1","H2","DH") after downloading the Macquarie stationXML to `./AUSPASS_dataless.xml` and Macquarie mseed data from AUSPASS into the folder structure:

> `AUSPASS-MSEEDS/<year>/<3 figure julday>/<year and 3 figure julday>_<time>_<sta>_<channel>.mseed`
> e.g. AUSPASS-MSEEDS/2020/366/2020366_000000_MRO27_HDH.mseed

This will produce data in an SDS format that can be used as input for `10_preprocess_all.py <ncores>`, which preprocesses the Macquarie data to a format suitable for ATaCR into the folder DATA.

Once `10_preprocess_all.py` finishes, open `11_generate_spectra.sh` and modify the path to miniconda as necessary and run `11_generate_spectra.sh` to generate ATaCR day spectra and day transfer functions. By default, this bash script runs on one core. However, if the machine has 15 cores free, the `&` at the end of line 42 can be uncommented for multicore running (or the script modified to use GNU parallel). A network pickle file required for this code is converted from AUSPASS_dataless.xml to AUSPASS_dataless.pkl (using https://schaefferaj.github.io/StDb/gen.html).

Now a catalogue can be downloaded to `catalogue.csv` and an event collection identified for a phase of interest (through filtering as required) and saved to `accepted-<phase>.csv`. `catalogue.csv` must contain the at least the headers: "LAT" (latitude in degrees) "LON" (longitude in degrees), "DEPTH" (depth in km), "DATE" (date in YYYY-MM-DD format), "TIME" (time in HH:MM:SS.milliseconds format), and `accepted-<phase>.csv` at least: `UTC` (UTC timestamp e.g. 2020-11-06T23:49:18.980000Z). The station dataframe is also required and included as `3F.csv`.

`12_process_event.py <phase> <ncores>` can then be run as a wrapper script for event waveform extraction and ATaCR denoise execution (delegated to a copy of `denoise_event.sh` with start and end times for station spectra populated), saving collections of denoised traces to the folder *denoised-data* (which can be renamed afterwards). This script may cut data from the DATA directory without reprocessing it (and just applying detrending and tapering), or from the SDS directory with reprocessing **using the exact same steps and parameters** as in `10_preprocess_all.py` (parameters on lines 62-75 in `12_process_event.py` is identical to those on lines 25-38 in `10_preprocess_all.py`, the the processing steps on lines 209-224 in `12_process_event.py` are equivalent to lines 87-101 in `10_preprocess_all.py`). Line 77 of `12_process_event.py` describes an upsample frequency to upsample waveforms (for use by adaptive stacking) before storing. In the study, to avoid excessive disk storage usage, no upsampling was performed for the initial identification of suitable events (i.e. when analysing all events from the catalogue), and set to 20 (Hz) for the accepted events in a reprocessing run.

Additional util scripts are also incuded: `identify_coverage.py` identifies the time ranges over which each station's channels recorded. `seismem2mseed.py` saves the most suitable denoise type (given a list of denoise type preferences in descending order) to miniseed. `plot_traces.py` plots collections of traces of different denoise types cut to the same relative time about their predicted arrival times into the folder *denoised-data/figures*.
